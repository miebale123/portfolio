# Procurement and invoicing tool: leading two interns

- **Company:** Ahaz Platforms PLC
- **Role:** Team lead for two engineering interns, alongside my main work on Ahazawi
- **When:** Early 2026, three months

**In short:** This was my first time being responsible for other people's work. The project was slipping, so instead of taking over the hard parts myself, I changed how the team worked. Within three months we shipped a VAT-aware procurement and invoicing tool that the company uses internally, and both interns were delivering features on their own.

## The problem

- Commits overwrote each other's changes.
- Features were built on guessed requirements, which the finance team later rejected.
- I reviewed work in the evenings after full days on Ahazawi, and progress kept slipping.

Taking over the hard parts myself would have shipped faster, but the interns would have learned nothing.

## What I changed

- **Weekly iterations**, each with one clear goal.
- **A Git workflow** with branches and reviewed pull requests.
- **One rule:** if a requirement is unclear, raise it with the team before writing code. Never guess.
- **Reviews that teach:** I reviewed every pull request and explained why I asked for each change instead of fixing the code myself.

## Results

- A VAT-aware procurement and invoicing tool, shipped and used internally.
- Both interns delivering features independently by the end of the three months.
